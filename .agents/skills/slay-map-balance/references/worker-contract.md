# Four equal Map workers

## Dispatch packet

Supply profile A–D, batch ID, exact seeds and assignment revision; repository/source SHA, latest main SHA, cohort/context ID and selected difficulty/policy/repetition manifest; pinned Master SOR/AGENTS/owner/audit and stable summaries/closed shards; exact isolated output directory or return-only instruction; requested evidence kind and definition of done.

Use the same scope and fields for all workers. Give each every difficulty and policy for its seeds. Initial round-robin registry allocation is stable and disjoint. Reassign only unstarted batches after confirming the previous owner stopped, recording the new ownership revision. Do not change case identities or erase results.

## Worker instructions

Read the pinned packet and $slay-map-balance. Confirm ownership. Read summaries first, then necessary raw. Analyze structure/routes, combat, Elite chains, recovery/Mystery, Shop, reward/deck/artifacts and boss entry across assigned conditions. Compare nominal ranks with equivalent-entry replay evidence; nominal rank does not establish measured difficulty.

Write only to the exact assigned findings directory, or return text for return-only tasks. Report missing evidence and continue independent work. Do not collect simulations, mutate journals, change stats/prices/generator/assets, write global reports, commit/push or spawn children. Do not average CP. Preserve historical source labels.

Return these fields (choose one reportKind):

- reportKind: SETUP_VALIDATION, STRUCTURAL, ESTIMATE or ENGINE_REANALYSIS.
- worker, batchId, assignmentRevision, sourceSha, cohortContextIds.
- assignedSeeds, completedSeeds, pendingSeeds.
- coverage: expectedCases and inspectedCases, null if unavailable.
- findings: category (MASALAH DISAHKAN/RISIKO BERPOTENSI/PENAMBAHBAIKAN), P0–P3, confidence, source/context/case/file evidence, effect, owner and action.
- limitations, evidence; activeSeconds and elapsedSeconds (null if unmeasured).

Mark completedSeeds only after the requested seed analysis is finished. Allocation planning completes no seed analysis. Keep zero findings when evidence establishes none. Do not invent timing, cases or coverage.

## Parent responsibilities

Freeze schedule/context, own collector/global calculations, inspect all reports, reconcile disjoint ownership/denominators, verify independently and publish once. Distinguish structural enumeration, observed prefixes, ten-node visits and victories. Label conditional survivor groups and overlapping risk groups.

Profiles are instructions, not separate read-only security sandboxes. Honor host permissions. Project TOML does not start background work, enforce ChatGPT Work limits, execute the batch plan or implement a collector shard selector. In Work the parent uses actual session subagent tools and enforces the four-worker cap.
