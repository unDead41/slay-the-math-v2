## Retained failures and test limits

The Tutorial provenance guard originally required the entire current `app.js` to equal the captured source. It now strips only the two exact optional hooks inside `showSaves` before comparing with the unchanged captured digest. An unrelated-runtime mutation still fails the guard; engine, original snapshots, image digests and all98pictures stay unchanged. Raw failed logs are preserved; filenames containing `green` are historical command names, not verdicts. In particular `cold-shell-green.log` crashed and is **FAIL**; only `cold-shell-diagnostic.log` and the final named native report pass. Early harness failures concerned navigator assumptions, iframe parse timing, an invalid manual Strength fixture,114exposures versus98unique pictures, duplicate Return controls and a legacy Stage2Knight fixture that intentionally uses its historical Stage1 fallback. Fixtures now use current Stage2Weaver; game rules/assets were not changed to satisfy tests. `portable-details-rerender-fail.log` records the fixture forgetting to reopen FAQ details after a Settings language re-render; the final run uses visible player controls.

Native Chromium also crashed during rapid Tutorial exposure on this machine. A later launch log explicitly reported zero temporary space and SIGTRAP. Removing the default disk-backed shared-memory flag and moving TMPDIR alone did not eliminate every Tutorial crash. The full14-check pass uses software graphics (`--disable-gpu`) matching existing Tutorial QA and normal shared memory, with the same production bytes. This establishes tested software rendering, not a proven GPU defect fix. Hardware graphics, physical devices, other browser families, OS reboot, human audio recognition and long-term browser eviction behavior remain unmeasured. The profile backing is tmpfs; the test proves actual CacheStorage survives browser-process closure, not survival of an OS restart. No sustained FPS claim.

## Risks and Master follow-up

- Browsers can deny persistence or clear all storage; final native persistence was false and the UI disclosed eviction risk. Reaudit before relying on offline play; clearing browser data always removes the installation.
- Offline URLs are release-pinned. After a run, use the ordinary game address with internet to check a new release; do not combine cached files from another manifest. Installed old namespaces are retained; a cache-cleanup UI is outside this request, so future releases may require more storage.
- A full installation is about233MB before HTTP compression and needs storage overhead. Online retains the existing initial loading budget; full Offline preparation truthfully permits longer than3minutes.
- The pet owner must use the published adapter/permission contract and add any future pet artwork/runtime/local files through the release build. No live provider/backend/key/animated pet integration is established here. Free-form API chat needs internet and explicit Online; Offline only supplies local FAQ/hint guidance.
