# Complete Player Tutorial Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans in this session, with a final fresh review. User requests completion end to end.

**Goal:** Ship a complete illustrated in-game tutorial with safe practical exercises.

**Architecture:** UMD chapter data and a testable controller own tutorial-only progress and independent engine examples. A DOM view mounts in the existing help dialog. Flat screenshot assets work with current production/portable packaging.

**Tech Stack:** Existing dependency-free JavaScript/CSS; Node test runner, jsdom and Playwright for QA.

**Spec:** `docs/superpowers/specs/2026-10-23-tutorial-design.md`.

## Global Constraints

- Preserve all gameplay rules, stable IDs, original artwork, audio and question-bank data.
- Persist only `slay-the-math.tutorial.v1`; practice never enters analytics or delivery.
- Read amounts from the loaded engine/configuration and render existing canonical questions/cards.
- Keep full English and BM copy and 44px controls; no hover/drag required.
- Work on `tutorial` from `d76ad6e`; publish a feature branch, not an automatic main merge.

## Review Focus

- Existing run/history/report survive tutorial, exercise, close and reload.
- Master definitions and language switches do not silently use ordinary amounts.
- Wrong answers, help, repeat clicks and replay cannot duplicate rewards or soft-lock.
- Unavailable/corrupt storage never blocks the guide or deletes unrelated records.
- Mobile/dialog scrolling, focus restoration, offline images and actual production entrypoints remain usable.
